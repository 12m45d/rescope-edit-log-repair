RULES FOR EVERY JOB THAT USES THE DRIVER (from its independent review; a violation invalidates the job)
  1. Gates and weights are IMMUTABLE.  Never modify detectors, thresholds, baselines, values or a weight tensor in place; every change
     is a new object: gate.replace(det_tau=...), fx.methods.mask_edits / wrap / fx.sweeps.raised_method, W.clone().
  2. At the end of every job:  rec = ses.assert_clean()   (= assert ses.stats["hook_mismatch"] == 0 and ses.memo.stats["conflicts"] == 0;
     every forward agreed with the predicted firing; no memo key has two outcomes).  Store rec with the results.
  3. ONE LOG PER PROCESS (one model handle, one session).  The only exception is the prefix builder, which reuses one model.
  4. Report the NUMBER OF CAPPED EDITS of every calibrated gate (fx.methods.n_capped(M) = M.rec["cal"]["n_edits_capped"]): its conformal
     bound is void for capped edits (the two-block cosine gate caps 23 to 58 edits on the LLaVA development log).
  5. Compare, deduplicate and cache methods by CONTENT: M.digest (fx.methods.dedupe), never by label or by M.key (the key hashes the
     record and misses the content of wrapped objects: review finding 2).
  6. Calibration sources: the REPAIR pool (default), BEN-S, MME-C.  source="benign" (the whole benign pool) raises unless a part is
     named; BEN-T and MME-T are TEST rows and raise wherever they are used as calibration, statistics or stream data; BEN-W is the
     statistics part of the feature packages.  Benign-pool and MME rows are gate level only (R19 e): fx.behave refuses them.
  7. Only the development logs, their working points and their prefixes may be used for anything behavioural or for any number that
     is looked at; every unseen log receives the frozen row set unchanged.

A log built later can be added at run time, also from another directory:

RULES THAT BIND EVERY EXPERIMENT (from the protocol and the project rules)
  * Only the development logs (fx.logs.names("development")) may be used for anything behavioural or for any number you look at
    before the final runs; on every other log this package ran mechanics only (open, build, one gate-level pass, 50 sequences; no
    metric).  Internal logs are never reported.  A registered log may not exist (fx.logs.available()).
  * Calibration queries and reported complaints come from the REPAIR pool (fx.draws); locality is reported on heldout_disjoint;
    pre-edit answers are the cached decoder-v2 answers (the key cache); nothing is tuned.
  * Every reported number is written by code (fx.io.Results) and rendered by script; per-row files are kept next to the results.
  * GPU jobs go through the queue:  $GQ run --mem 10500 (Qwen) | 17000 (LLaVA) -- python job.py ...   (fx.logs.load_model caps the
    process at GQ_MEM - 600 MiB).  Long jobs: nohup, log file, resumable -- the memo makes a restarted job skip what was computed.

CONVENTIONS
  * A SEQUENCE is a row of the backbone's key cache, addressed by its position j in the cache index (L.rows / L.pool / L.edit_rows return
    positions).  fx.behave rows carry sid (the library's sid, e.g. 'edit:tgen:17') and csid (the cache sid).
  * Calibration draw d: the n = 200 draw is rescope.splits.sample(valid REPAIR rows, 200, seed=d) (the draw of the library's USAGE and of the
    sanity experiment); the two-block split uses seed d.  Draws of other sizes are nested around it.  Draw indices 0 .. 19.
  * Every gate is built ON THE CPU from the log's files and the key cache (KeyCache.coords for calibration, as the library's usage
    example): gate-level and behavioural numbers refer to the same thresholds bit for bit, in every process.  A decision that lies inside
    the 1e-9 decision band is re-decided on the model's device with the hook's arithmetic (fx.behave), and every forward that runs is
    checked against the hook's own decision (ses.stats['hook_mismatch'] must be 0; assert it at the end of a job).
  * Released values: the library's rebased values V_i = U_i + sum over earlier batches of U_j <W_j, k_i>, computed batch by batch
    (fx.methods.released_values; equal to rescope.rebase to round-off, about 1e-15, checked at every construction).  Logs of one family
    then share the bits of the values of their common edits, so the memo is shared along T = 100 .. 2000.  rebase=False: the stored U_i.
  * Calibration keys.  Default (as the library's usage example and the sanity experiment): the TEACHER-FORCED key of each calibration query
    and of each own prompt; the conformal bound then covers teacher-forced firing.  Decode metrics (D2, free generation, wrong-target) are
    evaluated with the same gate at the decode's keys.  The library's rules 3 and 6 ask for every key of both paths if the bound is to cover
    decode metrics: build the rows with which="all", guards="all" (fx.methods.build(..., which="all", guards="all") or
    e1_rowset(..., which="all", guards="all")); Method.variant then says so.  Which of the two the paper reports is the PI's decision.
  * ReScope-N ('rescope_null', registered 2026-11-11 01:35; clarification of 09:03): benign sample A = the first 100 rows after position
    199 of the draw's ranking of the REPAIR pool whose QUERY (key-cache query_id: same question string and image content, hence the same
    key) is none of the 200 calibration queries and not yet in A: 100 distinct queries, none a calibration query (until 09:03 it was
    positions 200 .. 299, which shared 0 to 7 queries with the calibration draw; tests/t_cpu.py reproduces the 5 / 3 of draw 0 that the
    amendment names).  WHICH rows replace the dropped ones is this package's choice (the amendment does not say): the next rows of the
    same ranking.  fx.methods refuses ANY null-repair sample that shares a query with its calibration sample.  Then: library null_repair
    at ridge 0 on the teacher-forced last-prompt keys of A; guards added before the null repair as in every other row (the library
    counts guards the repair loses: rec['null_repair']['n_guards_lost']); the default two-block calibration on the 200 calibration
    queries.  Released values are unchanged.
  * Detector repairs driven by complaints (E2 d - f; amendment of 2026-11-11 01:50; CUT by R19, the functions remain and are tested).
    The parts of fx.draws.partition are disjoint as rows, not as queries (the pool repeats a few queries): before a repair that changes
    detectors, drop the complaint rows whose query is in the recalibration sample (fx.draws.query_ids; fx.methods raises otherwise).
    C0, S, C1 = fx.draws.partition(L, (160, 160, 160), draw) (E2 e - f: C0, C1 = partition(L, (200, 200), draw)); start =
    fx.methods.rescope(L, cal=C0); complaints arise on S; the repaired method is fx.methods.rescope(L, cal=C1, least=<complaints>) (least
    repair after recalibration), fx.methods.rescope(L, cal=C1, null_rows=<complaints>, null_ridge=0 | 0.1) (null repair, then calibration
    on C1), or the library's operators + fx.methods.recalibrate(L, S, cal=C1) + fx.methods.wrap.  The bound is claimed for thresholds
    calibrated on C1 only; records carry n_edits_capped and the detectors' norm inflation.
  * Guards: the stored solver keys and the B = 1 keys of the edits' own Rel prompts are added before every calibration (library rule 5);
    capped edits are counted in M.rec['cal'] (n_edits_capped, capped_edits) and M.rec['own_prompts'].
  * Methods with fixed (published) thresholds have no own-prompt guards: cosine 0.65 (NeuralDB), exact 0.999, ball radius 1.0 (GRACE eps_init),
    router eps = smallest own activation (WISE), z-score 2.2 (CoachHooK).  Scalar-score gates (router, z-score) are calibrated by ONE conformal
    threshold on their score from all n queries (calibration='conformal'); 'two_block' is available.
  * Rescope-WHERE = role 'all', fire 'all', response LIN without the round-off term.  where_logonly: tau_i = 5 % above the largest coordinate
    of edit i over every position of the other edits' own Rel sequences and the non-solver positions of its own (needs the model once per
    log: T truncated forwards; cached under memo/aux/<log>/).  where_least: the library's least_repair, one complaint at a time, library
    default on_conflict='refuse' (a complaint whose repair would silence an own key is refused and counted; on_conflict='partial' is a switch).
  * Hard negatives: valid rows of the final set (HN-I, HN-Q, HN-X; HN-X only if both edits are in the log).  own edit = the edit whose image
    (HN-I, HN-X) or question (HN-Q) the row uses.  wrong_target (gates) = the generated first line equals, after the testbed's normalisation,
    the target of the edit that fires in the decode; rows on which nothing fires in the decode are False without a decode (hn_stats: n_decoded;
    eq_own / eq_any_edit are rates over the DECODED rows only).  DUAL: wrong_target = the deployed answer was released.  Methods without firing
    flags (deployed weight, linear repairs): wrong_target is undefined (None); use eq_own / eq_any_edit.
  * fire='all' (ablation): every candidate edit releases, so coverage is own_cand (gate level) / own_fired_last (rows), not own_top.
  * Statistics: percentile bootstrap, 2000 resamples, seed 0; unit = query cluster for probe rows (row field query_id = the key cache's
    content id: rows with the same question string and image content are one unit; amendment R10; the library's own id, by image path, is
    the row field probe_query_id and gives the same clusters on the held-out pools), edit for edit rows and hard negatives.
    probe_stats(unit="uid") resamples probe items (the text and the image probe of an item together: the unit before R10; 248 instead
    of 449 units on heldout_disjoint of the Qwen development log).  The crossed bootstrap over calibration draws and units of R10 and
    the Holm correction: fx.stats.crossed_bootstrap / crossed_bootstrap_diff / holm (section EXTENSION).

THE MEMO (10_final/memo/<backbone>/shard_*.jsonl; fx.memo)
  key = (cache sid, mode 'tf' | 'prompt' | 'decode', signature); signature = sha1 of the fp64 value released at the last prompt position
  (scoped replay, REPL, top-1) or of a full replacement weight (deployed W_E).  A sequence on which nothing fires takes the cached
  pre-edit outcome of the key cache.  Entries are written only after a forward through rescope.Evaluator with the real gate and are shared
  by methods, draws, logs (same edit prefix, same values bit for bit) and experiments.  Per-process append-only shards, merged on read
  (ses.memo.refresh()): any number of processes may run at once.  Shards written by another version of the library (sha1 of rescope/*.py)
  are ignored and counted: ANY edit of the library empties the memo.  FX_MEMO_ACCEPT=<version>[,...] admits named versions (PI's decision).
  DUAL is composed from the memoised decodes of the deployed and of the pre-edit model (the pre-edit decode of a sequence is shared by
  every log of the backbone); the rule is the library's Dual.match (ses.dual_from_memo = False runs the library's own DUAL).
  Dense gates, teacher forcing: the router decides at the last prompt position, and a routed sequence has ONE outcome whatever the
  threshold (memoised under 'RW:<sha1 of W_E>'); a sequence whose largest z-score is below the z-score threshold is the pre-edit model
  (its score is cached per log under memo/aux/<log>/zscore_max.json), the others run through the library (ses.dense_fast = False: all do).
  Replacement weights (deployed W_E, P12's saved REEDIT / rollback weights) are memoised under the sha1 of the weight.
  Not memoised (library path, every row a forward): roles 'last+answer' / 'all', responses GAIN / LIN, fire 'all', adapter corrections
  (COMP), decodes of dense gates.  Role-'last' gates on that path still skip surely-silent sequences (rescope.SparseEvaluator).

SKELETON OF AN EXPERIMENT JOB
    L = fx.logs.open(name)
    # 1. gate level, 20 draws, CPU only (seconds per draw)
    per = {}
    for d in range(fx.draws.N_DRAWS):
        for M in fx.methods.e1_rowset(L, alpha, d, labels=("rescope", "cosine", "ball")):
            per.setdefault(M.label, {})[d] = fx.metrics.gate_stats(L, fx.gate.evaluate(L, M, positions=("tf", "prompt")))
    # 2. behaviour (GPU; restartable: the memo holds what was computed)
    H = fx.logs.load_model(name); ses = fx.behave.session(L, H)
    R = fx.io.Results("E1", out_dir)
    for d in draws:
        for M in fx.methods.e1_rowset(L, alpha, d, H=H):
            if M.kind == "dual": continue                       # generation only: ses.generate / ses.d2 / ses.hard_negatives(generate=True)
            e, p, h = ses.edits(M), ses.probes(M), ses.hard_negatives(M)
            kw = dict(alpha=M.alpha, n=M.n, draw=M.draw, variant=M.variant)
            R.add_nested(L.name, M.label, fx.metrics.edit_stats(e, ci=True), prefix="edit.", pool="edits", **kw)
            R.add_nested(L.name, M.label, fx.metrics.probe_stats(p, ci=True), prefix="probe.", pool="heldout_disjoint", **kw)
            R.rows(f"{L.name}__{M.label}__d{d}", e + p + h)
    assert ses.stats["hook_mismatch"] == 0 and ses.memo.stats["conflicts"] == 0      # every forward agreed with the predicted firing; no key with two outcomes
    R.save(); R.paper({...}); R.table(fx.io.pivot(R.records, row=("method",), col=("metric",), where=...))

LIMITATIONS (see also tests/out/table.txt)
  * Gates are CPU-built and release batch-by-batch rebased values; the library's usage example builds them on the model's device with
    rescope.rebase.  The two can differ in the last bits of thresholds and released values; test a compares every row with the sanity
    agent's GPU-built gates (and re-runs any differing row to establish the cause): see tests/out/table.txt.
  * fx.gate / the memo path cover gates that decide at the last prompt position (role 'last', fp64).  Everything else needs the model.
  * The router and z-score constructors, where_logonly (first use per log), where_least and p12 need the model's weights (H).
  * fx.behave evaluates sequences that have an item in the library's evaluation: edits, probe rows, valid hard negatives.  The benign
    pool is gate-level only (it has no pre-edit answer outside its 600-row subset).
  * DUAL costs two decodes per query the first time (both memoised afterwards); at scale use fx.draws.scale_edits and held-out probes only
    (amendment item 6).  Rescope-WHERE, the published cosine gate (role 'all') and COMP cost one forward per sequence and method; the
    z-score gate costs one truncated forward per sequence once per log + one forward per firing sequence for every calibration draw.
  * fx.gate decides on the CPU; a sequence inside the 1e-9 decision band (`near`: in practice the calibration query that defines eta, a
    REPAIR-pool row) can be decided otherwise by the hook (test c counts them).  fx.behave re-decides those rows with the hook's arithmetic.

KNOWN LIMITATIONS OF THE EXTENSION
  * fx.sweeps works for scoped gates with role 'last' and ONE detector per edit when guards are kept (the library's own_caps); gates with
    added detectors: guards="drop".  The literal threshold of a CAPPED detector is recomputed from the gate's own calibration (library
    two-block / shared rule with ranking baselines); a gate calibrated by another rule with capped edits needs literal= (ValueError says so).
    A gate calibrated WITHOUT guards (allow_silence=True) has no cap rule: guards="drop".  Gates that are not scoped logs (retrieval
    references) take part by offering .sweep(L, rows, which=, guards=, kc=) -> object with .at(delta), .gate(delta).
  * H3 can be unreachable with guards kept (caps hold edits in scope on fit rows): reachable False, read-out 'at_saturation'; it is then
    reported as unreachable, not replaced by the pure shift.  Coverage along the scale is monotone only without capped edits
    (coverage_scale reports 'monotone').
  * Key-level pools hold the last-prompt key only: scoped role-'last' gates and the router are decided on them; the z-score gate,
    Rescope-WHERE and every all-positions gate are not (NotImplementedError); no D1 and no behaviour on them (R19 e).
  * The guard recognises pool rows by their position in the key cache they belong to.  Keys handed over as TENSORS (null_keys=) cannot be
    traced to a pool: the caller states their origin (only bitwise equality with a teacher-forced calibration key is refused).
  * The crossed bootstrap resamples draws and units independently.  It is close to the analytic interval where the unit component
    dominates and CONSERVATIVE (too wide) where the cell noise dominates, as in paired differences (measured widths and coverages on
    synthetic two-way tables: tests/out/table_ext.txt, row "statistics"); with 3 behavioural draws the draw component is underestimated
    by about (n_draws - 1) / n_draws in variance.
  * Prefix logs: the intermediate weights of the original build were not stored; the prefix weight is the harness's reconstruction
    rule on the first batch updates (bitwise the deployed weight for all 10 batches).  D2 / decode fields of their probe records are
    None; rescope.load / stored_metrics / fx.logs.stored do not find them by name; fx.draws.verify_p12 has no records for them.
  * ses.tf_hashed costs one forward per sequence and method (0.1 s); hashes of two runs are comparable on the same card type and
    software only (bitwise determinism of B = 1 forwards was observed in every test, it is not guaranteed across hardware).
  * Method.digest hashes the detectors at every access (0.5 s at T = 2000); guard keys are not part of it.  The behavioural session
    keys its device copy of a gate by this digest (a gate changed in place is rebuilt, not served stale); the CPU feature cache of
    fx.gate is keyed by the detector OBJECTS and relies on rule 1 (hashing 176 MB of detectors per decision at T = 2000 would double
    the gate-level time).
  * The 'benign' part of fx.gate.evaluate / gate_stats / frontier is still the WHOLE benign pool (the first driver's read-out, kept
    unchanged); a reported far-locality column on benign rows is fx.pools.firing(L, M, "BEN-T").
  * The harness's own evaluate() / baseline() run on a prefix handle (their cache files go to cache_dir); they need about 4 minutes
    for the first call per log (the harness's eval cache) and are not needed for reported numbers, which are re-scored at B = 1
    through fx.behave (fx.methods.wrap of the correction or of its weight).
  * Dense gates (router, z-score): digest = (log, kind, threshold); their calibrated two-block per-edit form is not definable.

DEFINITIONS FIXED HERE (where the amendments leave a choice; none was made by looking at a result; to be confirmed by the coordinator)
  1. retr_sum / retr_min, top-1: the candidate with the largest MARGIN score - baseline (the two-block rule as the library defines it), not the
     largest raw fused score.  "R4 extended" says "top-1 by the fused score (retr_conj: by the sum of the two margins)".  The two readings differ
     only where several edits are candidates: 3 / 58 (Qwen) and 63 / 33 (LLaVA) of about 5560 sequences of a development log at draw 0.
  2. retr_min, standardisation: mean and POPULATION standard deviation (ddof 0) of the edit's block-1 scores; for the image cosine over the
     block-1 queries that HAVE an image (a text query has no image cosine).  Fixed before block 2 is read: the bound holds (synthetic test).
  3. The _x form of a SHARED-SCALE gate is the two-block _x form on the same detectors (cosine_shared -> cosine_x; fx.review1.x_form): R5 defines
     the construction inside the two-block rule only.  read_selection reports it (x_form_changes_calibration).
  4. Second form of the near-scope read-outs of an _x method (clarification (2) of 09:03), fx.review1.hn_unseen_foreign(L): a test hard negative
     is kept iff its FOREIGN part occurs in no recombination row the log may use -- HN-I: its question string (stripped, lower case) is the
     question of no recombination row; HN-Q: its image content (md5) is the image of no recombination row; HN-X: its partner edit b is the
     PARTNER of no X-X recombination row (as owner every edit occurs in its own rows).  Sizes on the development logs: HN-I 186 / 588 and
     178 / 590, HN-Q 434 / 591 and 465 / 597, HN-X 4 / 99 and 1 / 99: the HN-X subset is nearly empty; report the size next to every number.
  5. cos_null / rescope_null: the null-repair sample shares no QUERY with the calibration draw (fx.draws.null_sample; clarification (1)).  The
     white package's mechanics table used the ROW rule: reproduced exactly with that rule; with the driver's rule draw 0 differs, most for
     cos_null with the two-block rule on Qwen (tests/out/table_r1.txt, row "mechanics tables").

RETRIEVAL METHODS (Method.kind == "request")
  The decision depends on the query's image content and question string, not on a key: it is the same at 'tf', 'prompt', 'decode' and in every
  forward of a decode (on LLaVA also where lp_shift = 1; retr USAGE, section H).  Gate level: fx.gate.decide / evaluate dispatch to the rule
  (decisions carry near = False; top1=True works).  Behaviour: a sequence on which nothing is released is the cached pre-edit row (no forward);
  a sequence on which edit e is released runs through the memo path under the library gate that releases exactly e (feat2/retr forced_gate on
  fx.methods.base_gate(L): the value released is the driver's rebased value, so the memo entry is shared with every scoped gate that releases
  e on that sequence); the row's firing flags are the rule's decision.  Raised scale (fx.sweeps, H3): the common scale of EVERY attribute is
  shifted by delta, guards kept (retr_conj: both attribute thresholds); shifts accumulate (raising a raised method shifts it further; shift 0 is
  the method itself).  M.rec["cal"] holds eta, the bound, n_edits_capped / capped_edits and the own requests silenced by the literal rule
  (retr_conj: per attribute, with the bound that holds with the caps).
  Not defined for a retrieval Method: ses.tf_hashed (TypeError), fx.methods.mask_edits, M.rec["own_prompts"] (use gate_stats(...)["edit"]["rel"]),
  a session without the memo (fx.behave.session(L, H, memo=False) raises for it).

  H3: 0.1 s.  Measured first builds at T = 500 / 1000 / 2000 (s): a cosine-family gate 1 - 2 / 3 - 5 / 12 - 17; rescope_nullW 3 / 12 / 53 (the

  baseline x is computed once per detector set; cos_null_x and rescope_null_x: once per DRAW); retrieval rules and lookup: under 0.5 s at any T.

    the RESIDUAL RISKS every experiment agent must read); no line of fx/*.py was changed by that review (review_lean/patches.txt).

  * rescope_nullW nulls PROMPT-ONLY BEN-W keys (white USAGE, limitations); its record has no bitwise check against calibration keys (BEN-W
    shares no query with the REPAIR pool or with BEN-S of the VLKEB streams).

    quantile falls on the same query): M.digest is then equal, as it should; do not assume one digest per draw.
  * Importing white switches bytecode writing off for the process (sys.dont_write_bytecode); feat2/retr is appended to the END of sys.path.
  * TCosLog gates (cos_centred, whitecos) need feat2 on sys.path in any process that unpickles them; build them by name instead.

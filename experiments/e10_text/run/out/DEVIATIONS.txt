E10 (public ROME logs of GPT-2 XL): deviations and implementation choices; rendered by code/render.py (render2.py)
 1. driver fx: The shared driver 10_final/common/fx was being extended by other agents during the run; at 13:17 UTC its __init__ imported a module that did not exist yet and six E10 jobs stopped at import (no result lost: nothing had been computed).  E10 imports a FROZEN minimal copy (code/fx_frozen/fx: draws.py, io.py, stats.py byte-identical to the versions the adapter was tested with, sha1 79bb3a2819dc / 26e6a1349917 / 6a3cf7ff2965, and a reduced __init__).  The adapter's code fingerprint field 'fx' names the live directory, not this copy.
 2. R3 gates on text: The R3 gates are built by the feature layer 10_final/feat2/white (role 'all', rebased values, the adapter's guards and calibration).  Statistics: keys at all cached positions of 500 REPAIR-pool prompts that are in none of the 20 calibration draws (10k+ keys > d_in: the whitener's primal form).  cos_null: null repair on the keys (all positions) of the 100 prompts that the adapter's rescope_null would use in the same draw.
 3. patch of the per-position refinement: e10t.gate._scores_sub re-types the score formulas for lin / cos / ball detectors; for the query-normalised cosine gates (cos_centred, whitecos) the experiment routes the refinement through the gate's own scores at run time (code/xmeth.py); no file of the adapter is changed; tested (out/tests_gate.json, part b).
 4. gate level: Gate-level numbers come from code/xgate.py (per-position decisions on the GPU, one pass per feature for all draws), tested equal to the adapter's e10t.gate on the development log; thresholds are built on the CPU by the adapter's calibration.  Guards-off rows are also evaluated at gate level on T1000 / T2000.
 5. rows not run: rescope_shared, rescope_null (R21: not run).  Rows of the driver's row set that are undefined on these logs: e10t.methods.UNDEFINED (adapter's USAGE.txt): cosine_default (needs a marked write position), ball / router (decide at the last prompt position, where a subject-token key is never presented), zscore, dual (cut by R19), the P12 linear repairs (their text counterparts comp_min, rb_suffix, rb_lineage, blocklist are run).
 6. guards off / log-only: R21 (b) names the calibrated rows for the guards-off run; ReScope-W with log-only thresholds is subject to the same guard rule and is run both ways as well.
 7. least repair, two forms: sacrificing = library least_repair (on_conflict='force') from the log-only thresholds WITHOUT guards (allow_silence); protecting = library least_repair (on_conflict='refuse', complaint by complaint) from the log-only thresholds WITH guards.  Library margins (1e-6 relative): a complaint may stay inside the adapter's decision band; the table reports the share of complaints resolved as served.
 8. rb_suffix: Every prefix 1..T is replayed (float32, bit for bit) and tested on all complaints, stopping at the first unresolved batch; the longest resolving prefix is taken; forward passes of this scan are the repair's cost.
 9. comp_min: Minimum Frobenius-norm correction C with k (W_E + C) = k W_0 at every distinct complaint key and k_i C = 0 at every solver key (fp64, eigen-decomposition of the Gram matrix, relative cut-off 1e-10); served as float32(W_E + C); infeasible if distinct complaint keys + solver keys exceed 6400.
10. blocklist: Exact-match list on the prompt text; the public test prompts and the HELD-OUT prompts are never listed, so its rows equal the deployed log except for listed texts.
11. lookup_subject: String containment of the edit's subject in the prompt (decoded token ids, no clean-up); release at the token holding the last character of the occurrence; the latest edit wins a position; in a teacher-forced pass only the prompt is searched; in the public probability test the whole row (prompt + object).
12. R22: VIEW pool: continuation of the build's seeded permutation (REPAIR / HELD-OUT reproduced), records sharing a subject with any of the 2000 stream requests excluded, first 5000; report half = first 2500.  Complaint candidates: report-half views and aggregates whose deployed result differs from R*; m of them in a seeded order.  Keys of the complaints come from the diagnosis' pre-edit pass (no further pass charged).  Calibrated rows: draws 0-2.  Serving overhead measured on shared GPUs (noisy).
13. public score intervals: ES / PS / NS are the public summariser's numbers (it rounds to two decimals; calibrated rows: mean of the per-draw numbers); their intervals re-apply the summariser's per-record arithmetic to the public case files (agreement within the rounding is checked for every row).
14. serving overhead: out/r22/overhead.json: one process, warm-up pass, 7 interleaved repeats, median; shared GPUs.  The keyed store's string search is cached per prompt after the warm-up pass, so its timing covers the model call and the release only.
15. calibration-scale diagnostic: out/diag_eta.json (section 4) is a description added during the run to explain the outcome of expectation R21 (b): it recomputes the common scale eta of the two-block rule on the same calibration matrices with and without the detectors of the exploding updates.  Nothing is served with the recomputed scale and no row uses it.
16. certificate: Checked on every HELD-OUT prompt that a calibrated row leaves silent on the cached trace, in the batch layout of the behavioural runs; prompts inside the decision band are listed apart (the cache does not certify them).

RULES THAT BIND THE REGISTERED EXPERIMENT
  * The development log TX-G2XL-rome-dev100 (records from 15000) is the only log of the family on which a gating / repair method may
    be run or looked at before the registered experiment.  Everything in this package was run on it only; on the reported stream
    nothing was run (the key cache holds the two benign pools and the development log's prompts; the stream's parts are built by
    scripts/build_keycache.py --reported-ok when the experiment starts; scripts/run_rowset.py refuses a reported log without --reported-ok).
  * Create e10t.Backbone() BEFORE anything imports transformers: it sets up the build's stack (transformers 4.23.1 from ext/pydeps_tf4;
    under the environment's transformers 5.17 the public generate_fast emits garbage).  Importing e10t alone needs torch only.
  * GPU jobs go through the queue:  $GQ run --mem 13000 --prio -8 --name <tag> -- $PY <script>   (the Backbone caps the process at
    GQ_MEM - 600 MiB; measured peaks below).  Long jobs: nohup, log file; every part is resumable (store, case files, partial files).
  * Calibration queries come from the REPAIR pool, evaluation from the HELD-OUT pool; nothing is tuned; every number is written by
    code (JSON) and rendered by script (scripts/render_table.py).  Assert ses.stats["hook_mismatch"] == 0 at the end of a job (teacher-forced
    passes against the cached decision); report ses.stats["hook_mismatch_dec"] (decodes that left the cached continuation before a release).

THE SCOPED LOG ON A TEXT LOG (what "rescope" is here; nothing else differs from the default method)
  role set     ALL positions of the prompt and of the decode (the editor's position, the last subject token, is not marked in a served prompt).
               A query presents L + 10 keys: its L prompt tokens and the 10 tokens of the continuation.  The teacher-forced pass feeds
               [prompt, y0] (all ten tokens) and a decode feeds its tenth token once more, so that the hook sees exactly these positions.
               A release at the tenth continuation token cannot change the ten measured tokens; it counts as firing (gate.fired_last_only).
  detector     the logged right factor (read-out vector, d_in = 6400; the public code calls it left_vector) normalised to 1 at the solver
               key: W_i = left_vector_i / <left_vector_i, k_request_i> (library feature 'ncoord'); k_request = the key the public
               compute_v divides by (request prompt alone, last subject token), NOT the template-averaged key (builder's report, item 2).
  release      top-1 per position (largest margin (r - b) / u after the two-block calibration), response REPL: module output = W_0 k + b + V_i.
  values       rebased: V_i = U_i + sum over earlier updates j < i of U_j <W_j, k_i>  (one request per update: batch = arange; library rebase).
  calibration  two-block conformal rule, n = 200 benign prompts of the REPAIR pool (draw d = rescope.splits.sample(pool, 200, d); split seed d),
               alpha = 0.05; the score of a prompt = its maximum over the cached positions of the prompt and of the pre-edit continuation.
  guards       the stored solver keys and the key of every request AS SERVED (cached module input at the solver position of its own request
               prompt), added before calibrating; an edit whose guard the literal rule silences is capped and counted (rec["cal"]["n_edits_capped"]).
               ADAPTER RULE (not in the library): the library caps at (1 - 1e-9) x the guard coordinate, which presumes bit-identical keys; a
               prompt served in a padded batch has its key only up to float32 round-off, so a threshold whose guard lies inside the decision
               band is lowered until the guard is clear of the band (e10t.methods.guard_margin; rec["cal"]["guard_margin"]).  On the
               development log this touches exactly the capped thresholds (11 over 20 draws of the default method, relative change
               at most 8.2e-05); without it 8 of 30 capped edits did not fire on their own request as served
               (tests c_guard / g_guard).  served_guards=False gives the library's thresholds exactly.
  null repair  rescope_null: library null_repair (ridge 0) on the keys at ALL cached positions of n_A = 100 benign REPAIR prompts that share
               no text with the calibration draw (2508 keys of rank 2476 in draw 0 of the development log), then the default calibration.
  keys         inputs of the edited module under the PRE-EDIT model (upstream of the edited weight: they depend neither on the log nor on
               the method).  Key cache: float32.  float16 is NOT acceptable under the chosen guard band: it moves a normalised coordinate by
               4.3e-05 of its scale |w||k|/s, against 4.3e-07 between the cached key and the hook's live key (other batch layout, key-value
               cache); the decision band is 1e-05 of that scale.  Prompts inside the band are flagged `near` and always run through the hook.

ONE EXAMPLE PER METRIC (at most ten lines each; executed by the GPU test g_usage on the development log with the substitutions named there)
# ---------------- set-up (shared by the examples below)
import sys; sys.path.insert(0, "$RESCOPE_ROOT/02_research/experiments/10_final/e10_text/code")
import e10t, fx
B = e10t.Backbone()                                               # GPT-2 XL at W_0; first, before transformers is imported by anything else
L = e10t.open_log("TX-G2XL-rome-dev100")                          # registered experiment: "TX-G2XL-rome-T500" / "-T2000" (key cache parts first)
rows = {M.label: M for M in e10t.methods.rowset(L, alpha=0.05, draw=0)}       # the eight rows; M.rec holds draw, thresholds, capped edits
ses = e10t.behave.Session(L, B)                                   # sparse evaluation + on-disk store (a restarted job skips what was computed)
out_dir = e10t.OUT + "/example"
# ---------------- metric (i)
for lab, M in rows.items():                                       # (i) new object on request / paraphrase prompts, greedy decode, multi-token
    st = e10t.behave.edit_stats(ses.edits(M), ci=True)            # per kind: exact, token (stat dicts: value, ci_lo, ci_hi), own_released, ...
    print(lab, st["request"]["exact"]["value"], st["paraphrase"]["exact"]["value"], st["paraphrase"]["token"]["value"])
assert ses.stats["hook_mismatch"] == 0                            # every forward agreed with the cached decision
# ---------------- metric (ii)
for lab, M in rows.items():                                       # (ii) public scores: the public probability test on the served model + summarize.py
    sc = e10t.public.scores(ses, M, out_dir + "/public")          # case files under <out_dir>/public/<log>/<label>/run_000 (resumable)
    print(lab, sc["ES"], sc["PS"], sc["NS"], sc["EM"], sc["PM"], sc["NM"], sc["S"], sc["rows_fired_pct"])
# ---------------- metric (iii)
for lab, M in rows.items():                                       # (iii) D1 on HELD-OUT benign and on neighbourhood prompts (tf and decode variant)
    ho = e10t.behave.probe_stats(ses.probes(M, "heldout"), ci=True)
    nb = e10t.behave.probe_stats(ses.probes(M, "neighborhood"), ci=True)
    print(lab, ho["D1_tf"]["value"], ho["D1_dec"]["value"], ho["clean"]["D1_tf"]["value"], ho["tok_loc"]["value"], nb["D1_tf"]["value"], nb["D1_dec"]["value"])
# ---------------- metric (iv)
per = {}                                                          # (iv) gate level over the calibration draws: CPU, key cache only (no Backbone needed)
for d in range(e10t.N_DRAWS):
    for M in e10t.methods.rowset(L, alpha=0.05, draw=d, labels=("rescope", "rescope_shared", "rescope_null", "cosine")):
        st = e10t.gate.gate_stats(L, e10t.gate.evaluate(L, M, parts=("heldout", "paraphrase", "neighborhood")))
        per.setdefault(M.label, []).append((st["heldout"]["fired"], st["paraphrase"]["own_released"], st["neighborhood"]["fired"]))
print({lab: [fx.stats.over_draws([v[i] for v in vs])["mean"] for i in range(3)] for lab, vs in per.items()})     # false firing, coverage, firing NB
# ---------------- metric (v)
ref = None                                                        # (v) degeneration: n-gram entropy of the public generations
for lab in ("preedit", "deployed", "rescope"):
    path = f"{out_dir}/gen_{L.name}_{lab}.json"
    g = e10t.public.generation(ses, rows[lab], path, records=L.records[:100])      # public generate_fast + n_gram_entropy, seeded as the build
    ref = g["per_text"] if lab == "preedit" else ref
    g = e10t.public.generation_summary(e10t.data.jload(path)["rows"], ref)
    print(lab, g["GE"], g["pct_below_ref_q01"], g.get("prompts_fired_pct"))
# ---------------- metric (vi)
for T in (100, 500, 1000, 2000):                                  # (vi) retention: the first 100 requests of the stream as T grows
    LT = e10t.open_log("TX-G2XL-rome-T2000", T=T)                 # a registered prefix is opened as that log (stored deployed weight)
    sT = e10t.behave.Session(LT, B)
    for M in e10t.methods.rowset(LT, alpha=0.05, draw=0, labels=("deployed", "rescope", "where_twoblock")):    # deployed, default, thresholds-only repair
        st = e10t.behave.edit_stats(sT.edits(M, first=100))
        sc = e10t.public.scores(sT, M, out_dir + "/public", first=100)
        print(T, M.label, st["request"]["exact"]["value"], st["paraphrase"]["exact"]["value"], sc["ES"], sc["PS"], sc["NS"])

KNOWN LIMITATIONS
  * One edited module (transformer.h.17.mlp.c_proj of GPT-2 XL); GPT-J is not wired (cut by R19).  Right padding only.
  * Inside B.served(gate) call the model with KEYWORD arguments (input_ids=, attention_mask=, past_key_values=), as the package and the
    public code do: the hook learns the PAD positions and the continuation of a key-value-cache decode from them.  A mask passed
    positionally, or a padded batch without a mask, is not detected: PAD positions would then fire and be counted.
  * Prompts outside the build's prompt table (e.g. the VIEW pool of R16) have no cached keys and no stored continuation: the sparse
    Session does not cover them.  Serve them directly: with B.served(obj): tok, fin = B.decode(list_of_token_id_lists, n=1,
    feed_last=False) (first token of the greedy continuation; every prompt costs one forward).
  * The 'last-only' count of the behavioural rows is recorded for top-1 gates only (the ReScope-W rows show 0 there; their gate-level
    value is in the gate-level table).
  * The sparse evaluation asserts that a prompt on which nothing fires yields the stored pre-edit continuation (model = pre-edit model bit
    for bit; test g_silent).  The stored continuation was decoded by the build in unpadded batches; a padded batch can flip a near-tie
    token of the PRE-EDIT model itself.  The pre-edit row (which runs every prompt) measures that floor: on the development log D1 of the
    pre-edit row is 0.0 % on 4000 prompts.  On a firing prompt the row is whatever the batched pass gives (logits move by
    about 2e-04 between a batched and a single pass; no token differed on 600 rows of test g_batch).
  * The conformal bound covers the calibrated event only: a benign prompt exchangeable with the calibration prompts, at the positions of
    the prompt and of its 10-token continuation.  Other passes present other positions and are outside it: the public probability test
    (prompt + object), the public generation (up to 100 tokens), and the continuation of a prompt on which an edit was released (the
    decode leaves y0).  Capped edits are outside it as well and are counted.  Near-scope benign prompts (subject shared with / mentioned
    in / equal to a logged prompt) stay in the pools, as registered; they are flagged (clean / near columns).
  * Cached decisions are exact up to the decision band; inside it the hook decides and the row is flagged (`near`).  The cache is tied to
    the pre-edit weight (sha256 in every part's meta.json) and to the build's token ids; a changed tokenizer would not be detected.
  * Identity (c) (target attained at the solver key with rebased values) holds to the write round-off of the log: 6.5e-07 on the
    development log.  On a log with very large updates the dropped round-off term E k_i of earlier writes is larger; measure it per log.
  * NOT MEASURED, FORESEEABLE.  A request whose subject is the first prompt token has a division factor of about 0.02 (builder's report:
    8 such requests in the stream, 3 of them before update 500; none in the development log), i.e. a detector that is 1 at the own key
    and of the order of 50 at ordinary positions (ordinary detectors: about 0.1 there, division factor about 10).  Its calibrated
    threshold then lies far above 1, the registered guard rule caps it at the own key (coordinate 1), and a capped detector is a
    candidate wherever its coordinate exceeds the cap: at a large share of all positions of all prompts (top-1 ranks it below edits
    that pass their own calibrated threshold, so it releases wherever no other edit does).  If so, the default method inherits a
    collapse from a handful of capped edits.  No method was run on a reported log, so this is arithmetic, not a result; the records
    count capped edits (rec["cal"]["capped_edits"]), and allow_silence=True is the uncapped rule (those edits then never fire, their
    own request included).  Which of the two the paper reports should be decided before the reported logs are run.
  * The store trusts (method signature, prompt text): a gate's signature covers detectors, thresholds, ranking and values; a weight's is
    its sha1.  Outcomes written by another version of backbone.py / behave.py / gate.py are ignored.  Public case files and generation
    files are checked against the method's signature (refused if they belong to another method) but NOT against the code version:
    after a change of the package, give scripts/run_rowset.py a new --tag (or an empty out/<tag>/ directory).
  * Timings were taken on shared GPUs.
